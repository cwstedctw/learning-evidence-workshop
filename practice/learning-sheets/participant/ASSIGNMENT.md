# 成員任務：先自己評，再看AI

**合成示範、不是學生作答**。這裡的assignment是你今天要完成的練習；`data/`及`submissions/`是被評的合成作業，兩者不同。

1. 讀 `RUBRIC.md`。先只開 submissions/ 的 S01、S06、S10 三份文字紀錄，在 `templates/manual-first.csv` 填五區0／20、總分、判斷及理由；另存到自己的成果資料夾。先不要開講師答案、跑計分工具或看AI結果。這三份是指定校準，不是隨機抽樣。
2. 貼 `PROMPTS.md` 的第一段，讓AI只讀規準與 `data/submissions-10.csv` 原文，先提出五區試評與證據，保存 `ai-scores.csv` 和 `ai-evidence.md`。15份選做時兩處都改15；不要只保留10個代號的模板。
3. 三份人工表與AI表都保存後，再貼第二段請AI代跑Python工具。它從原文確定性判完成並加總，與AI試評逐區比較；數字不一致會列出，不會用AI的錯分蓋掉工具結果。
4. 自己核對三份人工表、AI證據、程式結果。另存並填 `templates/teacher-review.csv`：每筆選「採用／改分／待確認」、寫理由；確認後才填final_score。採用是你決定採用哪個有證據的分數，不是預先接受AI；待確認時final_score留空。15份版用 teacher-review-15.csv。兩份模板都未預填最終分數或決定。
5. 請AI把你的合成練習成果存Git版本，只加入這次成果路徑，版本說明寫你改了哪一處及原因；不建立遠端、不上傳、不碰其他資料。完成後看版本清單與差異。若工具沒裝好，可先保存檔案，版本操作標待補。

交件四組：人工三份表、AI試評與證據、工具結果及教師決定表、一頁教學調整設計。不要把老師的理由交給AI代填。可以記「本次沒有分歧」；不必為了練習捏造AI錯誤。

原工作台一頁設計可寫：本週看到哪些完成區／缺答、下次要改哪個提示、還要蒐什麼才能判斷改動有用。不要把10份合成練習寫成70人12場研究結果。

沒有Python：直接照規準手算，表格保留五區證據及總分，教師照常決定；標「未做程式核對」。不必先安裝Python，也不能把未跑寫成已通過。
